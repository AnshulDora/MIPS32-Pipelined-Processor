5-Stage Pipelined MIPS32 Processor Core (with Data Forwarding)A cycle-accurate, 5-stage pipelined MIPS32-inspired RISC processor core implemented in synthesizable Verilog. This repository features a fully functional behavioral datapath with hardware hazard management (Data Forwarding) and a macro-based verification testbench.📂 Project Structure/rtl: Contains the core hardware implementation file (mips32_risc.v). This acts as the structural hardware template containing pipeline registers, hazard units, and execution datapath blocks./tb: Contains the verification suite (tb_mips32_risc.v). This file acts as the simulation engine that loads programs into instruction memory, drives the two-phase clocking scheme, and monitors execution.🛠️ Project Design & ArchitectureMain Processor Core (/rtl)The hardware maps execution stages cleanly across a two-phase split clocking layout (clk1 and clk2) using specialized inter-stage pipeline registers (if_id_ir, id_ex_ir, ex_mem_ir, mem_wb_ir).Instruction Fetch (IF): Reads instructions out of memory using the current Program Counter (pc) register. Handles dynamic PC updates and pipeline flushes on taken branches.Instruction Decode (ID): Extracts operand source locations and reads data from the 32-element register bank (reg_bank). Sign-extends immediate values and decodes jump/branch targets.Execute (EX): Resolves mathematical/logical operations (ADD, SUB, AND, OR, SLT, ADDI) via the ALU and evaluates conditional branch flags (BEQ).Hazard Unit: Includes an dynamic Forwarding Unit that detects RAW (Read-After-Write) data dependencies across EX/MEM and MEM/WB stages and routes updated values into alu_in_a and alu_in_b in real time.Memory Access (MEM): Dispatches load/store transactions directly targeting data memory blocks (data_mem) for LW and SW instructions.Write Back (WB): Commits arithmetic or memory outputs into the register bank. To prevent structural read/write conflicts, register writes occur on clk1 while register reads occur on clk2.⚡ Hazard Handling & Forwarding LogicUnlike baseline pipeline designs that require software stalls or NOP insertion, this core includes hardware-level data forwarding:EX-to-EX Forwarding (Priority 1): If an instruction in the EX stage depends on the result of an immediately preceding instruction currently in EX/MEM, the result is forwarded directly from ex_mem_aluout.MEM-to-EX Forwarding (Priority 2): If an instruction depends on a result two cycles prior currently in MEM/WB, the result is forwarded directly from mem_wb_aluout (or mem_wb_lmd for LW).Branch Flushing: On a taken BEQ, the core flushes the instructions in the IF and ID stages to ensure incorrect speculative instructions are not executed.Note on Data Hazards: Thanks to the integrated forwarding unit, NOP instructions are no longer required between consecutive arithmetic/logical dependent instructions!🔄 Customization: How to Write Your Own ProgramsThe provided testbench uses behavioral macro tasks to assemble machine code directly into the instruction memory during testbench initialization. No external compiler or assembler is needed to run code.Available Instruction Tasks SyntaxWhen configuring program sequences inside the testbench, you can use these macro commands:addi(rt, rs, immediate); $\rightarrow$ Adds a sign-extended 16-bit constant value to register rs and saves it in rt.add(rd, rs, rt); $\rightarrow$ Adds rs and rt, saving the result in rd.sub(rd, rs, rt); $\rightarrow$ Subtracts rt from rs and stores the output in rd.and_op(rd, rs, rt); $\rightarrow$ Bitwise AND between rs and rt, saved in rd.or_op(rd, rs, rt); $\rightarrow$ Bitwise OR between rs and rt, saved in rd.slt(rd, rs, rt); $\rightarrow$ Sets rd = 1 if rs < rt, otherwise sets rd = 0.lw(rt, offset, base); $\rightarrow$ Loads a word from memory address base + offset into register rt.sw(rt, offset, base); $\rightarrow$ Stores the word from register rt into memory address base + offset.beq(rs, rt, offset); $\rightarrow$ Branch to PC offset if rs == rt.halt; $\rightarrow$ Stops processor execution.
